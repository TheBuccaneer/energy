## 3) Messpipeline (E2E)

**Ziel:** Zeit und Energie **konsistent über dasselbe Fenster** messen: **H2D → Kernel → D2H**.

**Ablauf (pro Lauf):**

1. **Vorbereitung:** Pinned Host‑Buffer (für echte Async‑Kopien), ein **Stream** für alle Operationen.
2. **Events/Start:** `EventStart` **vor erster H2D** enqueuen (im selben Stream).
3. **Abschnitt:** H2D (async) → Kernel (cuBLAS) → D2H (async).
4. **Events/Stop:** `EventStop` **nach letzter D2H** enqueuen; anschließend `cudaEventSynchronize(EventStop)`.
5. **Zeiten:**

   * `seconds_gpu` = **E2E‑GPU‑Zeit** aus Events (Start↔Stop, gleicher Stream).
   * `seconds_wall` = Host‑Walltime (Start/Stop um denselben Abschnitt).
6. **Energie (NVML‑Δ):** `E0` vor Abschnitt, `E1` nach Abschnitt → `energy_j = (E1−E0)/1000`.
7. **Abgeleitet:** `avg_power_w = energy_j / seconds_wall`, `edp_wall = energy_j * seconds_wall`.

**Wichtige Hygienepunkte:**

* **Pinned Memory** zwingend für echte Async‑Transfers (sonst de‑facto synchron).
* **Ein Stream** für H2D/Kernel/D2H und Events (präzise Fenster‑Klammer).
* **Host‑Sync erst nach Stop‑Event** (gezielte Barriere, kein unnötiges Device‑Global‑Sync).

---

## 4) Telemetrie & Throttling

Wir loggen pro Lauf:

* **Takt/Temp:** `clocks_sm_mhz`, `clocks_mem_mhz`, `temp_c`.
* **Throttle‑Reasons:** `throttle_reasons` (Bitmaske; 0 = kein Throttling). Damit können Thermal‑/Power‑/User‑Limits transparent nachgewiesen werden.
* **PCIe‑Status:** `pcie_gen_current`, `pcie_width_current` (zur Erkennung von Link‑Downshifts).

---

## 5) CSV‑Schema (aktuell)

```
timestamp, host, gpu_name, matrix_size, mode, batches,
seconds_target, seconds_gpu, seconds_wall,
energy_j, avg_power_w, below_target,
pcie_gen_current, pcie_width_current,
clocks_sm_mhz, clocks_mem_mhz, temp_c, throttle_reasons
```

**Hinweise:**

* `seconds_gpu` = **E2E‑GPU‑Zeit** (Events über H2D→Kernel→D2H).
* `seconds_wall` = Host‑E2E; beide Zeiten sollten eng beisammen liegen (wall ≥ gpu).
* `avg_power_w` ist redundant (prüfbar via `energy_j/seconds_wall`).
* Optional (empfohlen): `repeat`, `edp_wall` (Exporter kann es direkt mitschreiben).

---

## 6) QC‑Prozess

**Ziel:** Prüfen, ob die Daten **verwendbar** sind (präzise, konsistent, plausibel).

**Checks (automatisiert):**

1. **Schema & Typen**: Pflichtspalten vorhanden, Typen numerisch.
2. **Sanity**: keine negativen Zeiten/Energien; `seconds_wall ≥ seconds_gpu` (mit Epsilon).
3. **Leistungskohärenz**: `energy_j/seconds_wall ≈ avg_power_w` (Toleranz im Promille‑Bereich).
4. **Streuung (CV)** je (GPU×Größe×Mode) für `seconds_wall`, `energy_j` (Gate **≤ 15 %**).
5. **Ausreißer**: robust via **MAD** je Gruppe (Flag/Review, kein Auto‑Drop).
6. **Monotonie‑Hinweis**: Median(zeit/energie) vs. Größe; leichte Verletzungen erlaubt (Kachel-/Cache‑/PCIe‑Effekte).
7. **Thermal/Throttle**: Falls `throttle_reasons != 0`, Messung markieren und analysieren.

**Ergebnis (aktuelle Datei, 2025‑10‑09):** QC‑Gates komfortabel eingehalten; keine Red Flags.

---

## 7) Grenzen & Annahmen

* **Energiepfad:** GPU‑Energie (NVML). System‑gesamt (CPU/RAM/NIC) ist **nicht** enthalten; für GPU‑Fußabdruck okay, für System‑Footprint als Limitation dokumentiert.
* **Counter‑Semantik:** NVML‑Energie ist **kumuliert** seit Treiber‑Reload → immer **Differenz** pro Lauf bilden; Reload/Overflows im Log festhalten.
* **Pinned Memory:** sparsam einsetzen (Ressource); große Buffer wiederverwenden.
* **Streams:** Mehrfach‑Streams erfordern saubere Fenster‑Definition (Events je Stream oder konsolidiert synchronisieren).

---

## 8) AP4 — CO₂‑/Kosten‑Anreicherung (ohne Neu‑Messung)

**Zusatzfelder (pro Lauf):**

```
pue, grid_zone, ci_source, ci_value_g_per_kwh, eur_per_kwh, notes
```

**Formeln:**

* IT‑Energie (kWh): `E_it = energy_j / 3_600_000`
* Facility‑Energie: `E_fac = E_it * pue`
* Emissionen (kg CO₂e): `C_job = E_fac * (ci_value_g_per_kwh / 1000)`
* Kosten (€): `cost = E_fac * eur_per_kwh`
  **Datenfluss:** per (`timestamp`,`grid_zone`) mit CI‑Zeitreihen joinen (ElectricityMaps avg/forecast **oder** WattTime marginal/MOER). `pue`/`eur_per_kwh` als Konstante oder Zeitreihe.
